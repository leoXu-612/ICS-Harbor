# Harbor 架构

采用 SwiftUI + 少量 AppKit 面板，SwiftPM 构建。没有 Web 前端、本地 HTTP 服务、后台常驻守护进程或额外包管理器。

| 层 | 职责 |
| --- | --- |
| `HarborCore` | 数据模型、只读 Steam 清单解析、路径解析、卷标识、启动与配置策略、状态持久化 |
| `AppModel` | UI 状态、后台扫描、有限进程请求、日志和操作确认 |
| `Views` | 游戏库、独立应用、详情检查器、容器与磁盘、预设、任务、设置 |
| `Resources/bootstrap.sh` | 固定组件下载与哈希校验、新建专用运行时、Win32 探测；可选安装 Steam |
| `script` | 本地构建、生成自有图标、签名检查、预览打包 |

## 交互归属

运行环境提供 Wine、图形配置和盘符。Steam 是环境内的启动器，而不是运行环境本身。`SteamSessionControls` 只出现在运行环境页，集中展示该环境的 Steam 状态、启动/显示和正常退出。

游戏详情负责该游戏的启动、进度和配置，不重复持有 Steam 的生命周期控件。Steam 游戏启动仍走既有的按需启动客户端路径。“正常退出 Steam”与“结束 Wine 环境”分开，后者仍遵守托管标识、运行状态和显式确认。

Steam 游戏保留原模型与扫描策略。`WindowsApplication` 单独保存容器、EXE、工作目录和 argv；通过既有 `WSS-installer` 请求入口调用 Wine `cmd/start/msiexec`，不引入第二套运行时。`ContainerPurpose` 的缺省值保留旧 Steam 行为，新通用环境只初始化 prefix。

`ApplicationManagement` 管理安装/启动请求，复用 `LaunchProgress` 和 `LaunchProbe` 的进程归属、窗口检查及记录。独立程序有单独的“程序”检查点，不填充 Steam 检查点和连接状态。安装器返回码通过每次请求独有的文件回传；返回码为 0 不等于安装后应用功能验收。

新通用环境下载校验过的 Noto 中文字体，使用固定 `cjk-fonts.cmd` 配置该环境的常用字体替代，并检查完成标记。只作用于 UUID 匹配的 Harbor 托管环境；已有完成标记时不重复改字体设置。不会修改宿主或关联容器，也不会复制其账号或字体。

## 必须保持的约束

1. 关联容器默认只读。用户明确授权后，`RuntimeControl` 先原子保存、逐字节验证原始 Info.plist，并把授权绑定到容器 UUID 与规范路径，才开放有限图形参数写入。不会将关联容器变为托管容器。初始化和依赖安装仍仅作用于匹配 UUID 托管标记的容器；盘符修复仍单独确认。
2. 每款游戏以容器 UUID + Steam App ID 标识。不同容器里的相同游戏不共用预设或收藏。
3. 应用预设前保存 Info.plist 副本。只更新 D3DMETAL、DXVK、WINEESYNC、WINEMSYNC、METAL_HUD、WINEDEBUG 和 HarborSessionEnvironment；“继承”来自创建/授权时保存的基线，不能意外继承上一款游戏的覆盖项。程序路径、启动脚本和其他字段保留。
4. 不在活跃运行时切换图形环境。托管环境强制退出必须显式确认，不使用全局 `killall wine`。
5. 游戏路径只来自本地清单，执行请求只接受数字 App ID，经 Sikarugir 的 `launcher WSS-installer` 路径启动固定 Steam 程序。没有任意 shell 命令输入框。
6. 卷绑定使用 UUID；离线保持游戏记录、禁用启动，不新建同名库或触发下载。
7. Mac 原生 Steam 与 Wine 登记同一可解析目录时阻止启动，不自动改库。
8. Harbor.app 不包含可变 Wine prefix。运行时放在应用数据目录。资源定位必须以已安装 app 为根，不依赖 `.build`。
9. 保存状态采用原子写入和上一版备份。坏文件不会被空状态静默覆盖。移除列表记录不删除容器内容。
10. EXE/MSI 入口由用户在原生文件面板选择。只做文件类型和可读性检查，不把文件头验证宣称为安全认证。新安装要求 UUID 匹配的托管环境且无活跃 Wine 进程，关联环境只导入已有 EXE。
11. 独立启动参数逐项编码，不把用户输入拼成未引用命令；禁用延迟变量展开、转义百分号、拒绝双引号与控制字符。文件仅经已有盘符访问，不为启动偷偷新增映射。移除应用只移除记录，不卸载。

## 参数执行

`GamePreset` 从有限枚举生成 DXMT_CONFIG 和 MTL_HUD_ENABLED，不接受任意 shell 命令。环境变量通过已有启动器的 Process.environment 传入。`HarborSessionEnvironment` 仅记录 Harbor 本次选择的变量，启动器不执行该字段；用它检测“上一款游戏有环境变量覆盖、下一款恢复默认”的热切换风险。

DXMT 选项需满足后端匹配和本地 DLL 能力检查。变更/恢复配置需要环境停止；单独冷启动 Steam 会恢复基线，聚焦已有 Steam 不重设参数。启动进度、等待提醒和置前请求属于 Harbor 行为，不需要图形修改授权。旧 metalHUD=false 预设按继承读取，旧 enabled 同步保留双开语义。

## 验证边界

核心测试验证清单、策略和文件写入；原生 UI 验证组件与动作；窗口截图验证启动后的画面。它们分别提供证据，不能互相冒充。

固定版本意味着可重复，不意味着永不过期。第三方组件升级需核实来源、更新锁定哈希、重新跑初始化与游戏测试。此版不做静默升级。
