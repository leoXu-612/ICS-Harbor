# ICS-Harbor

A native macOS manager for Windows applications and Steam games, powered by Wine.

ICS-Harbor 是 ICS 系列的原生 macOS Windows 应用与 Steam 游戏管理器。Harbor 意为“港湾”，沿用已有帆船标识与应用名称。0.4.0 是可在本机运行的开发预览，不是已公证的公开正式发行版。

仓库与项目名称为 **ICS-Harbor**；应用仍为 `Harbor.app`，现有数据目录、Bundle ID 和容器路径不变，不因项目命名而迁移用户数据。

Harbor 不捆绑 Windows、Steam、Wine 引擎或游戏。它管理独立环境，按需从固定的官方地址下载运行组件，并校验 SHA-256。Harbor 自身代码使用 MIT 许可；第三方组件有各自的许可。

这里的“容器”是 Wine 的运行目录，不是安全隔离的虚拟机。不要用它运行不可信程序。

## 使用

解压 `Harbor-0.4.0-Preview.zip`，将 `Harbor.app` 放入“应用程序”，双击打开。此预览为 Apple Silicon 构建，需要 macOS 14.6 或更新版本和 Rosetta。首次准备组件下载约 266 MB，容器所在盘需至少 10 GiB 可用空间，应用与游戏空间另计。

### 独立 Windows 应用

1. **新建托管容器 → 通用应用 · 不装 Steam**。只准备独立 Wine 环境及开源 Noto 中文字体，不下载 Steam 安装器。新通用环境首次下载约 283 MB；不复制宿主或其他容器的字体。
2. **Windows 应用 → 安装 EXE / MSI…**，选择已准备的托管环境与可信安装包。环境中有程序运行时会停止安装派发，不强制关闭。EXE 使用 Wine `start /wait`，MSI 使用 Wine 自带 `msiexec /i … /norestart`；不静默接受许可，不自动登录。
3. 在安装器中完成安装后，点击 **添加已安装 EXE…**，选程序本身（例如 `drive_c/Program Files/7-Zip/7zFM.exe`），不要再次选择安装器。也支持已解压的便携 EXE，文件不会复制或移动。
4. 可以设置显示名称、工作目录和启动参数。**参数每行一个完整值，不加外层引号**；不支持内嵌双引号、控制字符或 Shell 命令片段。
5. 点 **启动应用**，状态条观察“磁盘 → 环境 → 程序 → 窗口”，不依赖 Steam、不显示虚构的 Steam 连接状态。程序自己的菜单负责正常退出。入口可编辑、在 Finder 显示或移除；移除入口不卸载软件、不删除文档。

当前安装仅面向 Harbor 托管环境，以免改变已关联的游戏容器。关联容器可导入已有 EXE 入口。普通应用使用原始环境参数；若之前的游戏参数尚在运行中，切换前必须先正常退出该环境内的程序。通用环境可以在运行环境页选择额外安装 Steam，但不是必需步骤。

安装器退出码为 0 只说明安装器正常返回，不证明安装后应用可用。Harbor 明示“安装器已结束”，需要选择已安装 EXE 并验证核心功能。不会递归扫全盘、自动运行发现的 EXE、自动装一堆运行库或承诺任意 Windows 软件兼容；依赖/版本需按应用确认。GUI、命令行软件均可登记；命令行软件没有窗口时不虚报窗口完成。

### Steam 游戏

1. 已有 Sikarugir 容器：首次启动会识别常用目录。也可点右上角 **+ → 关联现有 Wine 容器**，选择其 `.app`。关联不会复制账号、游戏、存档或初始化原环境。
2. 没有容器：**+ → 新建托管容器 → Steam 游戏**，命名并下载。进度在“启动与任务”显示。Steam 原版安装器出现后，请本人完成安装、许可、登录和 Steam Guard。保持默认 Steam 安装路径。
3. 在该容器的 Steam 中安装游戏，然后回到 Harbor 刷新。点游戏卡片，选择“启动游戏”。封面只读取本机 Steam 缓存；没有封面时显示占位图。
4. 外置盘在“运行环境”检查。Harbor 可在确认后建立缺失的 Wine 盘符，按卷 UUID 识别磁盘，不覆盖已有不同映射。**盘符映射与 Steam 库登记是两个步骤**，后者仍需在 Wine Steam 的设置中确认。macOS 若弹出外置盘访问确认，请本人允许 Harbor 访问所选磁盘；无需完整磁盘访问权限。
5. 在游戏详情点“游戏参数…”，按显示与性能、同步与兼容性、诊断、启动行为四组保存预设。关联容器默认只读；明确允许后先保存原始配置，再开放有限图形参数管理。关联身份、存档、键位和插件不改变。

### 统一管理启动器

Steam 的启动、显示窗口、在线状态和正常退出统一放在“运行环境 → 所属环境 → Steam”中；游戏详情不再重复提供“打开 Steam”按钮。点击“启动游戏”仍会按需唤起它需要的 Steam，不要求提前手动启动客户端。

运行环境、启动器和游戏是三个不同层次。“正常退出 Steam”不是结束整个 Wine 环境；结束托管环境仍是单独确认的高级操作。Steam 游戏仍自动发现，独立 EXE 从 Windows 应用页的入口运行，不依赖 Steam 的开关。

“正常退出”仅向 Steam 发送正常退出请求。“结束环境”仅向选定的 Harbor 托管运行时发送终止请求，会关闭其中所有 Windows 程序，使用前必须保存。关闭 Harbor 本身不会自动强杀游戏。

### 启动状态条

点击启动后立即显示“磁盘 → 环境 → Steam → 游戏 → 窗口”的真实检查点、已等待时间和 Steam 连接状态。在“启动与任务”可以查看最近检查时间和明细。重复点击不会重复派发同一环境的待处理启动请求。

阶段条不是剩余时间预测。默认 45 秒没有新状态时会提示等待较久，可在游戏参数中调整提醒阈值，但不擅自判定卡死。“停止跟踪”只停止观察，不会强杀 Steam 或游戏。Steam 有已记录的下载字节时才显示下载百分比，并注明计数时间。游戏窗口出现后，游戏内匹配、地图加载和实际响应仍以游戏画面为准。

### 预设含义

| 选项 | 行为 |
| --- | --- |
| 继承 | 已授权环境恢复首次备份的对应参数；未授权关联容器不改配置 |
| DXMT | 使用该固定引擎提供的 Direct3D 10/11 → Metal 路径 |
| DXVK | 使用该引擎的另一条图形路径，用于逐游戏对照测试 |
| DXMT 显示参数 | 帧率上限、强制 SDR、独占全屏切换处理；按本地组件能力开放 |
| 同步 | 继承、原双开方式、仅 M-Sync、仅 E-Sync、关闭；不是 VSync |
| 诊断 | Metal HUD 继承/开/关；Wine 日志继承/仅错误/错误与警告 |
| 启动行为 | 自动进度、尝试置前、30/45/90/180 秒无变化提醒 |
| 恢复默认 / 载入上次 | 只调整编辑草稿，保存后下次启动生效 |

**按游戏保存，不等于每个游戏有独立的运行中环境。** 图形和同步参数会影响当前 Wine / Steam 会话；切换配置前必须正常退出其中的程序。Harbor 会阻止热切换，包括切回默认时残留的会话环境变量。单独冷启动 Steam 会恢复原始参数；显示已运行的 Steam 不改参数。运行环境的更多菜单还可以恢复原始图形参数。详细作用范围与来源见 [参数说明](docs/PARAMETERS.md)。

预设不是“保证提帧”的优化包。不提供 DirectX 12、反作弊、所有游戏兼容性或帧率保证。首版不自动下载 DLL 注入器、材质包或游戏补丁。

### Steam 库不要跨平台共用

Mac 原生 Steam 与 Wine Steam 不应登记同一个物理游戏库。Harbor 会对两者的本地 `libraryfolders.vdf` 做只读比较；发现冲突时阻止相关启动。它不会自动删除库、迁移游戏或改写 Mac Steam 配置。此检测不是对 Parallels、第三方 Steam 管理器或所有挂载方式的完整隔离。

## 数据位置与清理

Harbor 的记录、托管运行时和缓存位于 `~/Library/Application Support/Harbor`。关联游戏仍留在原来的磁盘。

| 子目录 | 内容 | 清理注意 |
| --- | --- | --- |
| `state.json` / `state.previous.json` | 列表、预设、收藏、绑定、任务记录 | 不含 Steam 登录凭据；错误时不会自动覆盖损坏文件 |
| `Containers` | 托管 Wine 运行时和 Windows 用户目录 | **可能包含账号、游戏与存档，不当作缓存删除** |
| `Cache` | 校验过的组件下载和断点文件 | 完成安装、没有任务运行后可删除；重建需重新下载 |
| `ConfigurationBackups` | 应用图形设置前的配置副本 | 保留用于排查和恢复 |
| `Logs` / `LaunchRequests` | 本地启动日志和固定参数请求文件 | 不自动上传；分享前应自行检查 |

“移除记录（保留文件）”只取消 Harbor 登记，绝不删除容器或存档。它不是释放游戏空间的按钮。自己的源码构建产物 `.build` 和 `dist` 可重建；保留最新应用和安装包后无需长期累积旧版本。

## 本地构建

需要 Xcode / Swift 工具链。本仓库不使用额外的 Swift 第三方依赖。

构建或替换 Harbor 前，先保存游戏并结束正在运行的 Sikarugir Wine 环境。开发预览使用 ad-hoc 签名，Wine 后台可能保留旧启动器的 macOS 权限归属；后台活着时替换/删除启动器，会导致外置盘出现“Access denied”。构建脚本现在会在发现活跃 Wine 后台时拒绝更新，而不是强杀游戏或继续替换应用。遇到该问题应正常退出 Steam、结束对应 Wine 环境后，从当前安装的 Harbor 重新打开，不需要重新下载游戏或授予完整磁盘访问权限。

```sh
cd ICS-Harbor
swift test
./script/build_and_run.sh --verify
```

真实 Wine 文件往返测试默认跳过。仅在专门的临时托管环境中安装可信的官方 7-Zip 后，可以显式运行 `HARBOR_SMOKE_WRAPPER=/absolute/test/Runtime.app swift test --filter StandaloneSmokeTests`。它会执行 Windows 7-Zip，创建并删除自己的临时测试文件；不要把未验证程序或日常使用的环境作为测试目标。

Codex 的 Run 按钮使用同一脚本。其他参数：`--build-only`、`--logs`、`--telemetry`、`--debug`。打包当前本地预览：

```sh
./script/package_local.sh
```

默认输出 `dist/Harbor-0.4.0-Preview.zip` 及 SHA-256。应用资源从 `.app/Contents/Resources` 读取，不依赖源码或 SwiftPM 的绝对构建路径。GUI 可用 `--data-root /absolute/test/path` 隔离验收数据。升级前应备份 `state.json`；回退旧版应用需使用对应的状态备份，避免旧版丢弃新增应用记录或无法读取新增任务类型。

## 状态与限制

- 当前只实现 Sikarugir 固定版本适配，不是任意 Wine/CrossOver 容器的通用迁移器。
- 运行时在 Harbor 自身签名包之外，可变数据不写进 Harbor.app。
- 本地为 ad-hoc 签名。下载到另一台 Mac 后可能触发 Gatekeeper；**不要全局关闭 Gatekeeper / SIP 或跳过哈希校验**。公开发布前应完成 Developer ID、hardened runtime、公证和许可复核。
- 缺少 Rosetta 时停止并给出操作说明，不替用户接受 Apple 许可。
- Steam 登录或许可界面需要本人完成。网络错误会保留断点；上游安装器更新导致校验不符时会停止，不自动信任新文件。
- “已安装”只依据清单与目录；“请求已发送”“观察到进程”“真实游戏画面”分别记录，互不替代。
